Why this matters in plain English — 4 things

1. Optimistic untick (item #1). The status badge used to wait for the network round-trip before flipping — a few hundred milliseconds — which felt like "didn't update." Now the cache flips synchronously and rolls back only if the server rejects. Visual change in <16ms instead of 300-800ms.

2. Creator-only delete (item #10). Until today the delete button was visible to anyone with task access and the backend silently deleted whoever's task it was. Now both layers enforce the rule: the icon is hidden when you're not the creator, and the API returns a clear 403 if anyone tries to force it via direct request. Tested live with two different users — the demo user can't delete tasks Sam created, and gets the right error if they try.

3. Saved categories (item #5). Before, typing "Marketing" today and "marketing" tomorrow created two different categories. Now the Category input is bound to a native <datalist> populated from a new GET /tasks/categories endpoint that returns every distinct category the workspace has ever used. Starts empty; grows as you create tasks.

4. AI generate live (item #11). The ANTHROPIC_API_KEY you set on Railway is now active in prod. The "Generate with AI" button on /tasks/create accepts a sentence, calls Claude directly, and pre-fills title / description / priority / category / time block / linked SOP / subtasks.
